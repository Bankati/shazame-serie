## Plan d'implémentation — U18 Liste de suivi

Décidé par Claude le 19 octobre 2026 ; validé par le fondateur (« continuons avec l'unité suivante »).

### Ce que nous construisons

Bouton « Ajouter à ma liste » / « Dans ma liste » (optimiste) sur la fenêtre de résultat et la fiche titre ; page « Ma liste » (affiches, retrait, compteur) ; limite 100 titres en gratuit (`WATCHLIST_FULL`), illimitée en Premium via `getEntitlement()` (toujours « gratuit » avant U22).

### Décisions prises

1. API `GET` / `POST` / `DELETE /api/watchlist` : zod, `Origin` vérifié sur les mutations, session vérifiée ; compte suspendu : lecture seule (`ACCOUNT_SUSPENDED` à l'écriture) ; ajout idempotent.
2. Limite vérifiée dans la transaction d'écriture, sous verrou consultatif par compte (`pg_advisory_xact_lock`) : deux ajouts simultanés ne dépassent jamais la limite.
3. `getEntitlement()` dans `src/server/billing/` : « gratuit » jusqu'à U22.
4. Visiteur : le bouton mène à la connexion, avec retour sur la page courante.
5. Bouton optimiste (état local mis à jour tout de suite, retour en arrière + message si le serveur refuse) ; fiches ISR : état chargé dans le navigateur (`GET /api/watchlist`), rechargé à chaque changement de session.
6. Page `/ma-liste` : affiches (plus récentes d'abord), compteur « n / 100 », état vide ; titres relus via le catalogue avec le même budget de 4 s que l'historique (lecture factorisée dans `src/server/catalog/title-lookup.ts`).
7. Lien « Ma liste » dans les menus.

### Vérification

- `test:db` : 101e ajout refusé, deux ajouts simultanés à 99 → un seul passe, idempotence, propriété, retrait.
- Unitaires : validation, origine, visiteur 401, suspendu, Premium simulé illimité.
- Playwright : visiteur → lien de connexion ; compte (job « Parcours compte ») : ajout depuis le résultat, page liste, retrait.

### Invariants concernés

- 7 : zod, session, propriété (filtre `user_id`) dans chaque route.
- 8 : routes et page n'appellent que `src/server/`.
