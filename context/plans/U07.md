## Plan d'implémentation — U07 Couche IA et adaptateur OpenAI

Validé par le fondateur le 15 octobre 2026.

### Ce que nous construisons

L'interface `VisionProvider.identify(images, contexte)` et son implémentation `OpenAIVisionProvider` (SDK `openai` 7.34.0, API Responses, sortie structurée `zodTextFormat`, revalidée par zod). Les 2 à 5 JPEG sont envoyés en base64 avec la consigne versionnée `identify.v1`. Le résultat contient la réponse validée (reconnu ou non, titre, titre original, année, type film / série / animé, saison et épisode éventuels, confiance 0 à 100, jusqu'à 3 alternatives) et les métadonnées d'appel (modèle, version de consigne, tentatives, latence, jetons, coût en micro-euros). Jusqu'à 3 tentatives (délais 0,5 s puis 1,5 s) sur panne passagère, délai de 12 s par tentative. Un refus ou une réponse non conforme devient une erreur, jamais un faux résultat.

### Vocabulaire validé

- **Réponse de l'IA** : objet JSON strict ; c'est le « titre proposé » attendu par U08.
- **Tentative** (RG16) : un appel au modèle ; au plus 3, seulement sur panne passagère (délai, 429, 5xx, connexion). « Non reconnu » n'est pas une panne.
- **Coût d'un appel** : jetons réels × tarif du modèle, converti en micro-euros (`USD_TO_EUR`), compté pour chaque tentative facturée.
- **Consigne `identify.v1`** : instruction versionnée, enregistrée avec chaque identification ; toute modification passe par l'eval (AD-11).

### Décisions prises

1. `OPENAI_VISION_MODEL` = `gpt-6.1-sol` par défaut ; `OPENAI_IMAGE_DETAIL` = `auto` par défaut ; second candidat de l'eval : `gpt-5.6-luna` (Q4, U13).
2. Tarifs dans une table datée (page tarifs OpenAI, 15 octobre 2026) ; modèle absent de la table → appel refusé (le plafond RG5 dépend du coût). `USD_TO_EUR` = 0,89222 (BCE, 15 octobre 2026), révisé chaque mois.
3. `store: false` : OpenAI ne conserve pas la réponse (RG7) ; nouvelles tentatives du SDK désactivées (gérées par nous).
4. SDK `openai` importé uniquement dans `src/server/ai/` (invariant 2), contrôlé par ESLint (`no-restricted-imports`). Garde de dépense en U14 ; le coût est calculé dès maintenant.
5. Tests : fournisseur et client simulés (tentatives, refus, réponse invalide, coût) ; appel réel en local `npm run test:ai` sur une image générée (aucune image de film protégée dans le dépôt).
6. Redis (option A, 15 octobre 2026) : sessions gérées par Supabase Auth ; Redis réservé au cache TMDB, aux quotas et à la limitation de débit.

### Hypothèses

- `gpt-6.1-sol` accepte les images (vérifié par l'appel réel).
- Le niveau de raisonnement (`OPENAI_REASONING_EFFORT`, facultatif) n'est envoyé que s'il est défini.

### Fichiers créés / modifiés

- `src/server/ai/pricing.ts` (+ test) — tarifs, conversion, coût.

- `src/server/ai/openai-vision-provider.ts` (+ test) — adaptateur.

### Comment le construire

1. Variables d'environnement ; règle ESLint.
2. Schémas, consigne, tarifs, tentatives + tests.
3. Adaptateur OpenAI + tests simulés.
4. Appel réel ; vérification du coût.
5. lint, typecheck, test, build ; `/review`, `/audit` ; commit et push sur `dev`.

### Vérification

- Tests simulés : 3 tentatives maximum, délais croissants, pas de nouvelle tentative sur 400 / refus, coût cumulé des tentatives facturées.
- Appel réel : objet conforme, coût cohérent avec les jetons.
- Aucun import `openai` hors de `src/server/ai/` (ESLint).

### Invariants concernés

- 1 : seules les images reçues sont envoyées, jamais stockées (`store: false`).
- 2 : SDK confiné à `src/server/ai/` ; coût calculé pour chaque appel (garde de dépense en U14).
- 9 : ni images, ni réponse brute, ni clé dans les journaux.
