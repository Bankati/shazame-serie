## Plan d'implémentation — U25 Back-office : tableau de bord

Validé par le fondateur le 22 novembre 2026 (plan court, mode accéléré).

### Ce que nous construisons
Une page `/admin` réservée au rôle admin (relu en base), dans une coquille dédiée `AdminShell` (barre latérale fixe sur desktop, sans effet décoratif), qui affiche les indicateurs du CDC 12.9 : utilisateurs, identifications par jour, taux de réussite, coût IA et revenus. Lecture seule : aucune mutation (les actions arrivent en U26).

### Vocabulaire validé
- « Utilisateur » : profil non supprimé (`deleted_at` nul). Nouveaux = créés sur la période.
- « Jour » : jour de Paris (`Europe/Paris`), comme le quota et la dépense.
- « Période » : les 30 derniers jours de Paris, aujourd'hui compris.
- « Taux de réussite » : identifications `outcome = shown` / toutes les identifications de la période (cache compris). Affiché aussi : part servie par le cache.
- « Revenus » : revenu mensuel récurrent **estimé** (MRR) à partir des abonnements donnant droit au Premium (`getEntitlement`, mêmes règles) : mensuel 2,99 €, annuel 24,99 € / 12. Les montants réellement encaissés restent dans Stripe (lien vers le tableau de bord Stripe).

### Décisions prises
- Accès : visiteur → `/connexion?suite=/admin` ; connecté non admin (ou suspendu) → `notFound()` (ne pas révéler l'existence du back-office). Décision pure `adminPageAccess()` testée.
- Données : une fonction serveur `loadAdminDashboard(db, now)` dans `src/server/admin/dashboard.ts`, requêtes Drizzle agrégées en SQL (`date_trunc` en `Europe/Paris`), sous `withQueryTimeout`. Les jours sans activité sont complétés à zéro côté serveur.
- Coût IA : `ai_spend_daily` (miroir durable) et plafond du jour lu dans `app_settings.ai_daily_cap_micro_eur`.
- Prix de l'estimation : constantes `PLAN_PRICE_CENTS` dans `src/server/billing/` (même valeur que les textes de tarifs).
- Interface : tuiles de chiffres + un tableau dense jour par jour (identifications, affichées, décomptées, cache, coût IA). Pas de graphique en V1 du tableau de bord.
- Page dynamique (`force-dynamic` implicite par la lecture des cookies), `robots: noindex`.

### Hypothèses
- Un seul admin ou quelques-uns ; volume V1 faible : les agrégations directes sur `identifications` suffisent (index existant sur `created_at` à vérifier).
- Pas d'entrée « Admin » dans la navigation : l'admin tape l'adresse `/admin` (lien éventuel en U26).
